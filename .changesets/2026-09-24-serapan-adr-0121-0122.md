# ADR-0121 dan ADR-0122 `awcms` mendapat vonisnya

`bun run audit:serapan` merah karena `ahliweb/awcms` menerbitkan dua keputusan
yang belum dibaca siapa pun di repo ini: ADR-0121 (7 September 2026) dan
ADR-0122 (22 September 2026).

- **ADR-0121 divonis `diperiksa`.** `defineTenantRoute`'s `authorize` mendapat
  bentuk ketiga — array any-of — supaya sebuah route tanpa izin yang sama untuk
  setiap pemanggilnya, seperti `PATCH /api/v1/media/objects/{id}`, tetap lolos
  chokepoint otorisasi SEBELUM validasi body, alih-alih memakai bentuk fungsi
  yang punya celah `heldPrepareRefusal`. Nol migrasi, nol perubahan izin, nol
  perubahan OpenAPI — ini perbaikan internal pipa otorisasi `awcms` sendiri
  untuk sebuah route admin terautentikasi yang tidak pernah dipanggil kredensial
  mesin baca-saja repo ini, jadi tidak ada yang berubah di sini.

- **ADR-0122 divonis `diperiksa`.** Admisi `omes_control`, modul domain baru di
  `awcms` untuk infrastruktur fleet/deployment/backup/job OMES — delapan tabel
  bertenant dengan RLS dipaksa, dan layar `/admin/*` miliknya sendiri, seluruhnya
  admin SISTEM di bawah atap `awcms` (ADR-0051/0055/0070, semuanya sudah diserap
  di baris atas). Tidak ada permukaan API yang dipanggil build ini, tidak ada
  jalur konten atau media, tidak ada kontrak konsumen yang tersentuh — peran
  repo ini berhenti di halaman publik dan permukaan admin USER opsional, dan
  manajemen infrastruktur OMES bukan salah satu dari keduanya.

Puncak buku besar naik dari ADR-0120 milik `awcms` ke ADR-0122 milik `awcms`;
`belum` tetap nol.
